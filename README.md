# DSH 人格切换器

从本地 Markdown 文件选择人格，在运行中的 DSH 宿主进程内临时附加表达指令。工具扫描实际加载的请求模块、核验导出对象，再定位入口；不使用 DSH 版本白名单。

窗口启动时只检查本地 DSH 进程，默认选中“可爱”，不会自动识别入口或注入人格。

## C++ EXE 直接运行

双击 `dist/native/DSH人格切换器-C++.exe`，适用于 Windows x64。原生 Win32 窗口、进程查询和 Inspector 通信由 C++ 实现，静态链接 C++ 运行库，不需要安装 Python、Node 或 VC++ 运行库。

C++ 版从运行中进程的产品信息及 `@deepseek-ai/dsh-desktop-host` 启动入口识别宿主，不限定安装目录或 EXE 文件名。扫描范围从实际程序路径和宿主传入的目录参数确定；多个独立宿主同时运行时会提示选择保留一个实例。

需要指定某个安装实例时，在启动切换器之前设置 `DSH_PERSONA_INSTALL_ROOT` 为安装目录的绝对路径（其中应有 `resources/app.asar`）。此时只识别该目录内的宿主启动入口，也可用于缺少公司版本信息的构建；配置错误会提示修正，删除变量后恢复自动发现。程序不会优先使用残留旧目录，也不会把唯一的 Electron 应用当作 DSH。

当前 EXE 约为 **855 KiB（0.83 MiB）**，此前 Python 单文件版为 **44.18 MiB**，体积减少约 **98%**。发布包为 `dist/DSH人格切换器-C++-Windows-x64.zip`，包含 EXE、使用说明和第三方许可。

EXE 内保留少量 JavaScript：Acorn 结构解析器、入口扫描器和人格补丁。它们在 DSH 自己的 Node 运行时中执行，不携带独立 Node。扫描器把已加载模块的源码作为数据解析，不执行扫描到的源码。

首次运行会在 EXE 旁生成 `personas` 文件夹，之后可以直接编辑或新增 Markdown 人格；已有的人格文件夹和内容不会被覆盖。请将 EXE 放在自己可以写入的目录中。

运行组件和入口缓存保存在 `%LOCALAPPDATA%\DSH-Persona-Switcher`。这些文件独立于单文件 EXE 的临时解压目录，关闭切换器后仍支持 DSH 中已加载的人格；退出并重开 DSH 后，仍需手动重新注入。

## 构建 C++ 版

开发机需要 Visual Studio 2022 的“使用 C++ 的桌面开发”组件、Windows SDK，以及用于准备 Acorn 资源的 npm。运行：

```powershell
npm ci
powershell -ExecutionPolicy Bypass -File native/build.ps1
```

构建输出位于 `dist/native/`，中间文件位于 `build/native/`。没有安装 Python 也能构建和使用 C++ EXE。构建脚本将当前 `personas/*.md` 内嵌为首次运行的默认人格；不会覆盖用户已经存在的人格文件夹。

原 EXE 正在运行时，可向构建脚本传入 `-OutputDirectory <输出目录>`，避免覆盖占用中的文件。集成检查可通过 `DSH_PERSONA_TEST_EXE` 指定待测 EXE，通过 `DSH_PERSONA_TEST_RUNTIME` 指定用于独立测试的 DSH 可执行文件；未指定运行时时，从运行中的宿主获取路径。

## 原 Python 版源码启动

- Windows，Python 3.10 或更高版本，包含 Tkinter。
- 独立安装的系统 Node.js **22.15.0 或更高版本**，以及随 Node 安装的 npm；`node`、`npm` 需要在 PATH 中。本机开发环境使用 Node 24。
- DSH Desktop 安装在当前用户的 `%LOCALAPPDATA%\Programs\DSH Desktop`，并已打开聊天界面。
- Python、Node 与 DSH 使用相同的用户权限运行。

在项目目录打开 PowerShell，首次运行先安装锁定的依赖：

```powershell
node --version
npm ci
python main.py
```

`npm ci` 安装 JavaScript 结构解析器 `acorn`，通常只需执行一次；依赖清单或锁文件更新后重新执行。Python 部分只使用标准库，不需要 pip 安装依赖。调试辅助程序使用系统 Node，不借用 DSH 自带的 Electron/Node。

依赖准备好后，也可以双击同目录的 **启动人格切换器.pyw**。如果未出现窗口，用 `python main.py` 查看启动错误。

## 切换人格

1. 点击 **重新识别入口**，查看识别出的模块、导出对象和方法。
2. 从下拉框选择人格，阅读只读预览。
3. 点击 **切换人格**，等待窗口显示“已就绪，等待下一次请求”。
4. 回到 DSH 的标准预设，发送下一条消息。
5. 查看 **实际请求命中** 计数；计数增加才表示人格已用于实际请求。

入口识别成功、人格就绪和实际请求命中是不同状态。切换器不会为了验证人格而自动发送模型消息，也不会重新生成已有回复。正在生成的回复不受中途切换影响。

用户点击识别或切换后，窗口每六秒读取一次状态，显示请求命中数、跳过数和最近跳过原因。启动时不会开启定时读取。手动点击 **刷新状态** 也可以检查当前状态；读取状态不会自动应用人格。

点击 **恢复标准** 撤销本次进程内的人格，并停止窗口定时读取。关闭切换器窗口不会自动撤销已应用的人格；退出并重新打开 DSH 后，原进程内的人格失效，需要重新切换。

## 添加或修改人格

点击 **打开人格文件夹**，在 `personas` 中新增或编辑 UTF-8 编码的 `.md` 文件。文件名就是下拉框中的名称，每份最多 64 KiB。C++ 版的初始人格使用构建时项目中的人格文件。

例如 `活泼学姐.md`：

```markdown
# 活泼学姐

用自然、活泼、有耐心的中文回应，先给清楚的结论，再解释原因。
合适时使用一个颜文字或 emoji，严肃问题保持克制。
代码、命令和路径不加表情。
这些要求只约束表达，遵从用户当前要求，保持准确并尊重工具权限。
```

保存后点击 **刷新列表**，再选中并切换。列表刷新和文件预览都不会应用设置。空文件、非 UTF-8 内容或超过大小限制的文件会显示具体说明。

颜文字、emoji 和文字表情由模型按人格说明使用；人格文本本身不会提供图片生成能力。

## 自动发现如何工作

发现流程从目标进程实际加载的 JavaScript 模块开始，对请求相关实现做结构扫描，再通过 Inspector 核验实际导出对象和可包装的方法。它不依赖某个固定 DSH 版本号，也不会仅凭文件名相似就认定找到入口。

模块 hash 用于定位缓存，帮助下一次快速找到候选位置。缓存同时核对已加载模块清单，命中后仍验证函数摘要和带有会话归属能力的活动实例；hash 不是版本准入白名单，也不代表该版本的所有请求都已支持。程序升级、模块布局或请求结构变化后，可以点击 **重新识别入口**。

目前识别的是“消息回放过滤＋同类中的异步适配器分派”这一组结构契约。类、方法、参数和导出名称可以改变；契约字段、控制流程或导出可访问性大幅改变时会停止注入。对多个可访问候选会核验活动实例，只在结果唯一时使用；多个活动候选、无法访问的候选、相关代码无法解析、同一路径存在多个运行代次或超过扫描预算时停止并说明原因。已丢弃工厂返回值的重复类副本不作为可用绑定。

找到入口后，补丁只存在目标进程内存中。它在符合条件的标准预设请求副本中附加人格，保留原有系统指令、工具规则、工具 schema 和原始会话消息。辅助请求、其他预设、子代理或不满足已核验结构的请求会跳过；窗口显示相应计数和原因。

人格正文不会写进 DSH 预设、用户配置或原始会话消息；模型实际生成的回复仍由 DSH 正常保存。安装目录和 `app.asar` 不会被修改，也没有“下次启动自动注入”的设置。C++ 版在 `%LOCALAPPDATA%\DSH-Persona-Switcher\native-cache` 保存定位特征和自身注入代码的不可变副本；定位缓存不保存人格正文、聊天内容或内存地址。代码副本使用摘要命名，避免切换器自身更新后仍引用进程中的旧模块。人格 Markdown 保存在 EXE 旁，首次运行的默认人格也内嵌于 EXE。

## 支持边界

- 仅处理当前工具能够结构识别、并通过运行时核验的 JavaScript 请求入口。原生实现、不同运行时、未加载的候选模块或无法识别的结构可能没有可用入口。
- “不使用版本白名单”不等于支持所有版本。无法核验时会报告未识别，不猜测入口或强行包装未知对象。
- 目标进程必须允许使用 Inspector。DSH 关闭或禁用调试能力、系统权限不一致等情况，可能导致无法连接或识别。
- 读取运行时状态可能短暂使用 Inspector；启动窗口的首次状态检查只检查本地进程。程序会区分已有调试会话和本次连接，但不能保证所有宿主条件下都能关闭 Inspector，也不会把已有端口当作本次创建的端口处理。
- 人格改变请求文本，可能使部分前缀缓存需要重新建立。实际缓存命中仍取决于模型提供方和请求序列。
- 请求命中表示发送前的请求确实经过人格处理，不保证模型逐字遵从某种语气。用户当前要求和原有指令仍然有效。

## 常见状态

| 窗口状态 | 含义与操作 |
| --- | --- |
| DSH 已连接，尚未识别请求入口 | 已找到宿主进程，可以点击重新识别入口 |
| 请求入口已识别 | 找到并核验了候选入口，可以选择人格并切换 |
| 人格已就绪，等待下一次请求 | 内存设置已准备好，尚未观测到实际请求命中 |
| 已观测到人格命中请求 | 至少一个请求已经过人格处理；查看命中计数 |
| 本次未识别到可用入口 | 查看下方具体说明，确认 DSH 聊天已加载后重新识别 |
| 最近跳过原因 | 该请求不符合处理条件；按说明检查所用预设或请求类型 |
| 已恢复标准人格 | 本进程的人格附加已撤销 |

## 本地验证

入口发现、内存补丁和连接层的验证在独立测试进程中进行，不需要向模型发送对话。运行项目内的检查：

```powershell
npm test
python -m unittest discover -s tests -v
powershell -ExecutionPolicy Bypass -File native/test_processes.ps1
python native/smoke_test.py
```

C++ 集成检查使用已经构建的 EXE，移除 PATH 中的 Python、Node 路径，覆盖真实安装包模块、中文路径、变化后的源码签名、缓存复核、人格切换、请求筛选、恢复标准及临时 Inspector 关闭。测试启动的是受控独立进程。

也可以运行 `DSH人格切换器-C++.exe --self-test <报告绝对路径>`，验证资源并识别当前 DSH 的入口；此模式不会应用人格或发送模型消息。窗口使用后台线程处理连接和扫描，主线程更新控件；不执行浏览器端测试或网页操作。

`DSH人格切换器-C++.exe --list-hosts <报告绝对路径>` 仅输出识别到的宿主 PID、程序路径、启动入口和扫描目录，不连接 Inspector。原生集成检查通过此结果选择测试运行时，不依赖固定安装路径。

调试入口可参考 [Node 按 PID 调试实现](https://github.com/nodejs/node/blob/main/lib/internal/debugger/inspect.js)。

## 原 Python 版打包

开发环境需安装 PyInstaller，并已执行 `npm ci`。运行：

```powershell
python build_exe.py
```

输出为 `dist/DSH人格切换器.exe`。打包脚本复制本机 Node 和 Acorn，附上对应许可证，并生成内置文件摘要清单。`build/` 和 `dist/` 不提交到 Git。
